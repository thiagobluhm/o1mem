Como o número é feito
  • Messages = o growth do log: a conversa acumulada que o /handover+/clear evita arrastar. É a economia.
  • Baseline = o piso pago sempre (system + tools + memória + CLAUDE.md). É o custo de retomar — pago dos dois jeitos, então não entra como economia.
  • R$ = Messages × preço input USD/1M do modelo × câmbio. O seletor é uma alavanca "e se fosse tal modelo?"; o câmbio é seu.
  • ⚠️ Contexto re-arrastado é re-lido como input, mas re-leitura cai no cache (~0,1×) — então o R$ é um teto, o pior caso sem cache.
  • ⏱️ Tempo de sessão = extrapolação de TEMPO a partir de TOKENS: o Claude Code não corta por relógio, corta quando a janela de contexto enche. Sem O(1)mem (branco) é o teto de UMA sessão: pega o ritmo REAL entre dois avisos da mesma sessão e extrapola até um teto de janela (constante WINDOW_CEILING no código, hoje ~1M — aproximação, não o limite exato de todo modelo) — onde ela travaria se ninguém rodasse /handover+/clear. Com O(1)mem (verde) NÃO é um teto novo — não existe mais teto, esse é o ponto do produto. É o MÚLTIPLO do teto de 1 sessão que o seu dia mais puxado já superou de verdade: soma o tempo ativo (exclui vãos > ACTIVE_GAP_CAP_HOURS entre avisos — hoje 2h, pausa ou virada de dia) em dias com 2+ sessões distintas, e divide pelo teto. Sessão com só 1 aviso, ou dia com só 1 sessão, não entram (sem 2º ponto no tempo não há ritmo pra medir).
